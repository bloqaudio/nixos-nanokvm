# C906L validation on the test host, 2026-09-16

## Scope and recovery

The SG2002 camera was connected directly to a USB host.
All board images were transferred through ROM into RAM; nothing was flashed.
The ISP/media blocks and camera-control buses remained Linux-owned.

The new opt-in `--uboot-watchdog` runner option arms WDT0 before C906L
validation: `TORR=0xff`, restart `0x76`, then reset-only `CR=1`, with readback.
At 19:40:02 CEST it was armed and deliberately left unfed. USB disconnected
at 19:41:28.543 and ROM `3346:1000` enumerated at 19:41:30.050. This proves
approximately 86-second reset-only recovery on this board, not just a configured
watchdog. `CR=3` is interrupt-then-reset and would take two periods; it is not
the tested recovery setting.

Linux's independent initrd/stage-2 keeper reported watchdog state `active` and
timeout `85`. Host-health loss also caused recovery: the first stalled USB
attempt returned to ROM at 19:45:23.750. A later successful test was ended by
removing only the test host address and stopping its NBD runner, then waiting
for watchdog recovery rather than resetting C906L under Linux.

The final run was ended the same way at 20:09:54 CEST. USB disconnected at
20:11:49.177 and ROM enumerated at 20:11:50.680, approximately 117 seconds
after withdrawing host health (health-failure detection plus watchdog expiry).
No physical reset or additional host reboot was needed. The dedicated USB
address, NBD server, debug listeners and USB log reader were removed/stopped.


## Firmware and activation

Base ABI 1.1 passed exact immutable-manifest validation and cache-evicted
heartbeat reads (`46 -> 49`). The all-timers profile subsequently passed the
same pre-Linux check while its leases were dormant (`45 -> 49`).

The matched Linux 7.2.0-rc5 image reserved firmware at `0x8fe00000` and shared
memory at `0x8ff00000`. Linux validated this contract:

```text
profile=all-timers profile_id=16 epoch=2 abi=1.1
sha256=2413b7f7122dcf010f6fefcf089bdaf5d9b239077c6aba92c910f7d14c0bde1d
final_capabilities=0x7f dormant_capabilities=0x0b lease_mask=0x0f
driver_outcome=completed state=4 error=0 attempts=1
```

Completion requires all four timer IRQ self-tests to succeed. They leave each
timer stopped and its IRQ disabled; this is not a long-running timer service.
Remoteproc attached the FSBL-started core and created the `rpmsg_chrdev` channel
at address `0x400`. No runtime unbind, unload, reattach or core-reset test was
performed.

## Baseline transport measurements

These are userspace round-trip measurements under this lab workload, not
hard real-time guarantees:

| Test | Exchanges | Median | p99 | Maximum |
| --- | ---: | ---: | ---: | ---: |
| Mailbox, including 16-bit sequence wrap | 65,537 | 148.880 us | 192.240 us | 2691.240 us |
| RPMsg, 496-byte changing payload | 1,000 | 4991.120 us | 5009.080 us | 6418.720 us |
| RPMsg, cycling all 1-496-byte lengths | 1,000 | 4993.560 us | 5028.400 us | 6216.280 us |

Firmware diagnostic flags remained zero, heartbeat advanced, and Linux reported
`kicks_dropped=0`. These initial RPMsg passes did not cross the 16-bit vring
index boundary.

The 5 ms RPMsg cadence exposed a notification-consumption issue: firmware
publishes both RX data and TX completion but alternates notifications through
one shared doorbell. Servicing only the indicated ring could leave a ready RX
reply waiting for the next FreeRTOS tick. The Linux handler now checks both
fixed rings, RX first, for either valid notification. The production-handler
regression test reproduces the delay's missed-RX condition before the fix and
passes afterward; invalid IDs and teardown guards remain checked.

## Reproducing the lab configuration

```console
nix build --builders '' --no-link --print-out-paths \
  .#boards.licheerv.mainline.live.usb-c906l-all-timers.usb-boot
```

Run that exact artifact on the physical USB host with `--uboot-watchdog`,
`NANOKVM_ATTACH=none` and a bounded ROM-transfer deadline. The runner serves a
read-only NBD root and configures the dedicated USB host address `10.55.0.2`.
Do not remove that address during testing: it is the keeper's health target.
Stopping NBD alone is not equivalent to withdrawing host health.

The final lab leaf disables the USB kernel console while retaining UART and
the TCP debug shell. This isolates console traffic; it is not proof that the
first USB stall was caused by console backpressure. A retained initrd status
process labels its snapshots `stage: initrd` even after switch-root, so that
label alone cannot diagnose a stuck initrd. Full-speed NBD startup took several
minutes, including a zram device timeout followed by successful zram creation.

## What this does not establish

The [GPIO/UART/I2C/SPI drivers](sg2002-c906l-peripheral-drivers.md) are dormant,
typed register drivers with host tests, not activated hardware services.
Controller/pin ownership, clocks, electrical timing, IRQ service integration
and physical tests still need board-specific work. No ISP firmware replacement,
arbitrary MMIO service, Linux peripheral proxy, bulk DMA service or runtime
C906L reset is provided by this campaign.
