# SG2002 C906L auxiliary core

## Status and scope

This tree contains opt-in, attach-only firmware for the SG2002's 700 MHz C906L
auxiliary RISC-V processor.  ABI 1.1 provides a generated, profile-specific
contract shared by firmware, FIP, device tree, the RAM-only runner, Linux
control and remoteproc modules, and a Rust diagnostic client.  It implements a
heartbeat, mailbox control, a fixed non-coherent RPMsg transport, and a
fail-closed static lease activation protocol.  An opt-in Timer4 lease performs
the first bounded IRQ self-test and advertises itself only after Linux has
acknowledged the exact contract.  Runtime core reset, generic bulk transfer,
and long-lived physical-peripheral services remain intentionally absent.

> **Hardware status (2026-09-04):** on the SG2002 attached to `strix-2`, C906L
> reached the Rust control task and published a valid ABI-1.0 RUNNING record.  Its
> heartbeat advanced from `0xae` to `0xc3` across two cache-evicted U-Boot reads,
> validating reset-vector execution, FreeRTOS scheduling, and C906L cache-clean
> publication.  The test also found and fixed U-Boot reclaiming the original
> top-of-RAM carveout.  A follow-up boot proved that the production firmware at
> `0x8fe00000` and status at `0x8ff00000` survive and that FSBL starts C906L on
> the tested USB BootROM path.  A subsequent Timer4 boot proved the corrected
> U-Boot LMB/EFI reservation, the IRQ-55 one-shot self-test, capability `0x7`,
> and the fully matched ABI-1.0 Linux/module/Rust-CLI path.  No persistent media
> has been written.  The ABI-1.1 manifest, RPMsg attach, and Linux-gated Timer4
> activation described below are built and host-tested but not yet validated
> on silicon.

By default all functional peripherals remain owned by Linux, or disabled under
Linux's control.  The C906L touches only its architectural startup state, its
PLIC path, its assigned AP-mailbox control channel, and the reserved DDR status
cacheline.  Selecting `timer4` additionally gives it that one timer channel;
shared clock/reset/source registers are validated read-only.  In particular,
ISP, CSI/VI, codecs, LDC, IVE, system DMA, and TDMA remain Linux-owned because
camera/ISP development is proceeding in parallel.  The C906L firmware must not
probe, reset, clock, pinmux, acknowledge, or DMA through those blocks.

In this project, “full peripheral support” does not mean giving C906L
unrestricted access to every address in the SoC memory map.  It means direct,
typed drivers for the C906L-routable controllers that can be statically and
exclusively leased without compromising Linux, plus narrow Linux/RPMsg proxy
services for unrouted, shared, or system-critical blocks.  A controller with a
C906L interrupt is only a candidate, not an entitlement; a mapped controller
without a C906L interrupt ordinarily remains Linux-owned.  This definition
keeps one accountable owner for every register bank, IRQ, pin, clock/reset,
DMA request, and buffer.

The feature is enabled with:

```nix
{
  sg2002.kernel = "mainline";
  sg2002.uboot = "mainline";
  sg2002.wifi.enable = false;
  sg2002.auxCore.enable = true;
  # Optional first peripheral lease; omit for mailbox/heartbeat only.
  sg2002.auxCore.peripherals = [ "timer4" ];
}
```

`sg2002.auxCore.enable` deliberately forces the firmware-bearing FIP, the DTB
with matching reservations, both Linux modules, and the profile-bound Rust
client as one unit.  It is currently rejected with the vendor kernel, vendor
U-Boot, or Wi-Fi DT variant.
Do not select the C906L FIP without its matching DTB: Linux could otherwise
allocate memory from underneath the running auxiliary core.

The repository also publishes a ready-to-run, atomically matched live image at
`boards.licheerv.mainline.live.usb-c906l.usb-boot`.  Prefer that catalog leaf
for bring-up; the standalone packages below remain useful for narrow build and
inspection checks.  The Timer4 lease has its own fully matched live runner at
`boards.licheerv.mainline.live.usb-c906l-timer4.usb-boot`.

## Processor and boot model

SG2002 has a selectable 1 GHz C906/Cortex-A53 application processor and a
separate 700 MHz C906L.  This project uses the primary C906 for OpenSBI/Linux
and the C906L as a physically addressed, M-mode RTOS processor.  The C906L is
not an SMP hart managed by Linux.  Its firmware is part of the trusted
computing base: M-mode and peripheral DMA mean that a firmware defect may be
able to corrupt Linux even though the DT reserves its normal working memory.

The boot chain is:

1. The SG2002 ROM loads the FIP.
2. The vendor FSBL loads the FIP's `BLCP_2ND` image at its explicit run address,
   checks its recorded checksum/range, cleans cache, supplies boot metadata, and
   starts C906L.  Reset-state and live-status observations establish that it
   does start C906L on the tested USB BootROM path; an earlier interpretation
   that USB boot skipped this step was wrong.
3. OpenSBI and U-Boot start the primary C906.  Once fastboot is available, the
   host runner validates two stable status/manifest snapshots: exact contract
   digest, epoch, profile, ABI, capabilities, lease policy, generation and an
   advancing heartbeat.  A lease profile must still be DORMANT; the runner
   never activates hardware.  If a future path instead leaves it held in reset,
   the runner first checks the exact payload CRC and performs the documented
   reset-vector/release sequence.  An already-running core not associated with
   this runner's FIP transfer is refused unless the operator explicitly selects
   `--accept-running-c906l` after independently proving the image identity.
4. Linux independently validates the DT, status and immutable manifest.  The
   control driver publishes a commit-last activation record for a lease
   profile and waits for exact ACTIVE status before exposing userspace.  The
   remoteproc driver then attaches the fixed RPMsg transport.  Neither driver
   starts, stops, resets, or loads code into C906L.

The packaged Sophgo fiptool is patched so RTOS selection is fail-safe.  A FIP
without `--rtos` has a zero-length payload and zero run address; an RTOS payload
requires an explicit nonzero `--rtos-runaddr`.  The FIP derivation then verifies
the packed bytes, padding, checksum, payload adjacency, and run address.  This
removes upstream fiptool's unsafe implicit bundled image and hard-coded
`0x83f40000` address.

Runtime reset is intentionally absent.  The TRM requires outstanding bus
transactions to be quiesced before resetting a processor or subsystem, and no
upstream SG2002 remoteproc/reset provider establishes that invariant.  The
vendor SDK's private syscall/SBI reset mechanism is not used.

## Exact memory and mailbox map

The supported board configuration has 256 MiB of DDR.  All ranges below are
physical and end-exclusive.

| Range | Size | Owner and purpose |
| --- | ---: | --- |
| `0x80000000..0x8fe00000` | 254 MiB | U-Boot/Linux RAM, subject to their ordinary reservations |
| `0x8fe00000..0x8ff00000` | 1 MiB | C906L firmware: executable image, data, BSS, FreeRTOS heap and stacks |
| `0x8ff00000..0x90000000` | 1 MiB | Versioned, non-coherent Linux/C906L shared-memory reservation |
| `0x8ff00000..0x8ff00040` | 64 B | C906L-written status cacheline described below |
| `0x8ff00040..0x8ff000c0` | 128 B | C906L-written immutable, commit-last contract manifest |
| `0x8ff000c0..0x8ff00140` | 128 B | Linux-written, commit-last activation request |
| `0x8ff01000..0x8ff02000` | 4 KiB | C906L-initialized remoteproc resource-table region; serialized table is 88 B |
| `0x8ff02000..0x8ff06000` | 16 KiB | RPMsg vring 0 |
| `0x8ff06000..0x8ff0a000` | 16 KiB | RPMsg vring 1 |
| `0x8ff0a000..0x8ff0c000` | 8 KiB | C906L trace reservation |
| `0x8ff10000..0x8ff50000` | 256 KiB | Fixed 512-byte RPMsg buffer pool |
| `0x8ff50000..0x90000000` | 704 KiB | Unassigned future bulk-data region |
| `0x01900000..0x01901000` | 4 KiB | AP mailbox controller, governed by Linux with a C906L endpoint |
| `0x019000d0..0x019000d2` | 2 B | Cross-core `SPIN_MBOX` hardware semaphore, field 4 of the mailbox spinlock bank |
| `0x01900400..0x01900440` | 64 B | Eight hardware payload slots; channels 0/1/2 are control, Linux-to-C906L vq kick, and C906L-to-Linux vq notification |

Both DDR carveouts are `reserved-memory` nodes with `no-map`.  The ELF verifier
checks the entry point and every loadable segment, including memory size rather
than only file size, against the firmware's 1 MiB range.  The shared region is
separate so a later transport cannot silently consume firmware heap/stack
space.

The placement follows Sipeed's board memory map: the final 2 MiB are FreeRTOS
memory and U-Boot/Linux see a 254 MiB ceiling.  The C906L U-Boot variant sets
`CONFIG_SYS_MEM_TOP_HIDE=0x200000`; without that contract U-Boot relocates its
malloc arena into the two carveouts and clears the running firmware.

`SYS_MEM_TOP_HIDE` alone is insufficient in this U-Boot version: relocation and
malloc use the reduced `gd->ram_top`, but LMB initially imports the complete DRAM
bank, allowing `bootm` or EFI page allocation inside the hidden 2 MiB.  The local
`lmb: respect SYS_MEM_TOP_HIDE for allocations` patch therefore enables
`CONFIG_LMB_LIMIT_DMA_BELOW_RAM_TOP` whenever the hide is nonzero.  Its existing
LMB path reserves the bank portion above `gd->ram_top`, so LMB and EFI share the
same ceiling.  The build asserts that both Kconfig settings survive
`olddefconfig` rather than silently accepting a future configuration change.

The code treats the C906L/Linux DDR path as non-coherent: C906L explicitly
invalidates before reading status, cleans after writing it, and brackets MMIO
and shared-memory publication with `fence iorw, iorw`.  Linux maps status as I/O
memory and reads it with `memcpy_fromio()`.  The TRM does not provide a
sufficiently explicit end-to-end coherency guarantee, so this remains a design
assumption that must be stress-tested on hardware.

Mailbox slots and enable bits are also shared state.  Every sender and receiver
therefore takes hardware semaphore field 4 before copying an eight-byte slot,
acknowledging pending state, or changing the destination enable byte.  A
nonzero low-byte token identifies Linux and a nonzero high-byte token identifies
C906L; write/readback equality acquires the field and a second write of the
owning token releases it.  A controller-wide Linux raw spinlock and local C906L
IRQ masking prevent same-participant recursion.  Acquisition is finitely
bounded; isolated IRQ misses leave the level interrupt unacknowledged for retry,
while sixteen consecutive misses mask the C906L mailbox source so the vendor
PLIC claim loop cannot livelock.  A task/start failure fails closed.  Callbacks
and FreeRTOS queue operations run only after the cross-core lock is released.

## Firmware layering and reproducibility

The package pins Milk-V's C906L FreeRTOS tree at
`10b86e308ca2305a464ae2bb3eb868a72295f7ab`.  It uses the vendor's established
reset entry, C906 CSR/cache helpers, linker script, PLIC setup, and FreeRTOS
port.  The build removes the vendor peripheral drivers and HAL selections,
replaces the vendor command-queue task with the local C shim, and suppresses
wall-clock build strings and UART output.  The prebuilt vendor audio library is
not linked.

The layers are deliberately small:

| Layer | Responsibility |
| --- | --- |
| Vendor assembly/BSP | C906L reset entry, CSR/cache setup, linker script, trap/PLIC foundation |
| FreeRTOS | Scheduler, bounded control/vq queues, control and RPMsg tasks, 200 Hz tick |
| Local C shim | Mailbox channel ISR and register sequencing, cache helpers, narrow C ABI into Rust |
| `no_std` Rust | Generated ABI types, manifest/activation, heartbeat, control service, RPMsg virtqueues/echo, typed Timer4 test |
| Linux mailbox core | Locally hardened upstream `sophgo,cv1800b-mailbox` controller, shared hardware semaphore, and IRQ 101 on the primary C906 |
| Local Linux control module | Exact-contract validation, sole activation-record writer, single-client misc device, stable sysfs identity |
| Local Linux remoteproc module | Attach-only fixed resource table, vrings and RPMsg buffer pool; no core lifecycle authority |

[`pkgs/sg2002/c906l-firmware/rtos-shim.c`](../pkgs/sg2002/c906l-firmware/rtos-shim.c),
[`firmware/sg2002-c906l/src/activation.rs`](../firmware/sg2002-c906l/src/activation.rs),
[`pkgs/sg2002/c906l-control/sg2002-c906l-control.c`](../pkgs/sg2002/c906l-control/sg2002-c906l-control.c),

and the canonical
[`pkgs/sg2002/c906l-contract/contract.json`](../pkgs/sg2002/c906l-contract/contract.json),
from which each profile's C, Rust, Python, kernel, and device-tree bindings are

Rust is built for `riscv64gc-unknown-none-elf`, using the medium code model, as
a sanitized static archive that the vendor link consumes.  Cargo is locked and
offline.  The final package emits a binary plus ELF, map, disassembly, and the
generated contract header.  `SOURCE_DATE_EPOCH` is fixed, the firmware must fit its
carveout, and the output is checked as ELF64/RISC-V.  Host tests cover the
wire layouts, command behavior, cache publication order, activation rejection
classes, idempotence, zero pre-authorization peripheral access,
resource-table/RPMsg bounds, Timer4 teardown, and tick-wrap arithmetic.

The local Rust is MIT and the upstream FreeRTOS kernel is MIT.  The broader
Cvitek/Milk-V BSP does not carry sufficiently clear per-file licensing, so the
combined firmware package is conservatively classified
`unfreeRedistributable`; it must not be represented as wholly MIT-licensed.

### Pinned BSP limitations and HAL direction

The pinned BSP is useful for reset, traps, cache operations, the PLIC, and the
FreeRTOS port; it is not a production peripheral HAL.  Its RISC-V driver build
list contains only common code, pinmux, UART, spinlock, GPIO, and a header-only
RTOS command queue.  The cv181x HAL build enables only UART and pinmux; its I2C
source is excluded, and there are no cv181x SPI, PWM, ADC, I2S, DMA, timer,
watchdog, or media drivers at this pin.  Specific defects prevent treating the
available code as safe driver coverage:

- GPIO output writes whole-bank `SWPORTA_DDR` and `SWPORTA_DR` values for a
  single pin, clobbering the configuration and output state of other pins.
  It has no input, state-read, interrupt, or error API.
- The high-level UART driver hard-codes UART0 and uses a global HAL instance.
  The HAL can wait forever for transmit-ready, and its receive function has an
  invalid control path when data is ready.  UART0 is also the rescue console.
- The excluded I2C HAL refers to undefined `IC3_INTR`, contains unbounded FIFO
  waits, and has unfinished locking.  It is neither built nor safe to enable.
- The pinmux HAL covers only a small fixed set of UART, I2C, and camera cases;
  it is not an ownership model for the SoC pin banks.

Consequently, new drivers should be clean, typed Rust implementations against
the controlling TRM rather than thin safe-looking wrappers around this vendor
C.  `embedded-hal` 1.0 can describe GPIO, I2C, SPI, and PWM behavior once those
drivers and ownership rules exist.  UART should use `embedded-io` (and perhaps
`embedded-hal-nb`), while timers, DMA, audio, watchdog, media, crypto, keyscan,
Wiegand, and most RTC functions need narrow project-specific APIs.  The current
`embedded_hal::delay::DelayNs` implementation is only a coarse FreeRTOS delay,
rounded to the 5 ms scheduler tick; it is not evidence of a hardware timer HAL.

The maintainable target is a small workspace with these boundaries:

| Crate/layer | Intended responsibility |
| --- | --- |
| `sg2002-pac` | Private volatile register blocks derived from the TRM, compile-time offset/size assertions, and singleton `Peripherals::take()` ownership |
| `sg2002-hal` | Drivers that consume PAC, lease, clock, pin, IRQ, DMA, and buffer tokens; `embedded-hal` implementations where its traits fit |
| `sg2002-bsp-sys` | Narrow FreeRTOS, PLIC, cache, and mailbox C FFI; no general vendor-driver façade |
| `sg2002-ipc` | One canonical `no_std` versioned ABI and generated C header for both firmware and Linux |
| Board crate | LicheeRV Nano pin aliases and the statically selected ownership manifest |
| Application/services | Policy and RPMsg endpoints; no public raw-pointer or arbitrary-MMIO escape hatch |

Register drivers should have host fake-MMIO tests, offset assertions, bounded
wait/error paths, and compile-fail tests for ownership tokens.  The board build
must additionally prove that its DT lease and firmware manifest agree.

## Control ABI

### Hardware transport

The AP mailbox has eight 8-byte payload slots.  Processor IDs are `1` for the
primary Linux C906 and `2` for C906L.  The DT specifier `<&mailbox 0 2>` assigns
physical channel 0 targeting C906L.  Requests and responses reuse slot 0; only
one transaction may be outstanding.

The mailbox is a control plane, not a data plane.  No physical address, native
pointer, variable-size structure, or bulk payload crosses this ABI.

### Eight-byte message

Every `write(2)` and successful `read(2)` transfers exactly one little-endian
word with this layout:

| Byte offset | Width | Field |
| ---: | ---: | --- |
| 0 | 1 | `service` |
| 1 | 1 | `opcode` |
| 2 | 2 | `sequence`, little-endian |
| 4 | 4 | `value`, little-endian |

ABI 1.1 defines service `1` (control) and these operations:

| Request opcode | Response opcode | Value |
| ---: | ---: | --- |
| `0x01` `PING` | `0x81` | Request value echoed unchanged |
| `0x02` `GET_ABI` | `0x82` | `(major << 16) | minor`, currently `0x00010001` |
| `0x03` `GET_CAPABILITIES` | `0x83` | Low 32 bits of the current status capability mask |
| `0x04` `ACTIVATE_LEASES` | `0x84` | Kernel-only activation result; envelope value is the request ID |
| Unknown service/opcode | `0xff` | Zero |

The response retains the request service and sequence.  Capability bit 0 is
the mailbox control service; bit 1 is the shared-memory heartbeat; bit 2 means
the selected Timer4 IRQ self-test passed; bit 3 is RPMsg.  The base profile is
ACTIVE with `0x0b`.  Timer4 is DORMANT with `0x0b` before Linux acknowledgement
and ACTIVE with `0x0f` only after the self-test passes.  Userspace cannot send
opcode `0x04`; the control driver is the sole Linux authority.  Consumers must
match sequences and require both ABI components and the exact profile mask.

### Status cacheline

The C906L is the sole writer of the 64-byte status record at `0x8ff00000`.
Linux is read-only.  All multibyte fields are little-endian.

| Offset | Type | Meaning |
| ---: | --- | --- |
| `0x00` | `u32` | Magic `0x4d564b4e` (`NKVM` in little-endian memory) |
| `0x04` | `u16` | ABI major, currently 1 |
| `0x06` | `u16` | ABI minor, currently 1 |
| `0x08` | `u32` | Structure size, currently 64 |
| `0x0c` | `u32` | State: 1 booting, 2 running, 3 fault |
| `0x10` | `u32` | Generation; increments when a valid preceding cacheline survives restart |
| `0x14` | `u32` | Flags: response timeout, request dropped, Timer4 test failed, activation rejected/failed, manifest fault, terminal mailbox-lock failure, or an unexpected mailbox channel (bits 0-7) |
| `0x18` | `u64` | Heartbeat; increments every 20 RTOS ticks, nominally 10 Hz |
| `0x20` | `u64` | Capability bitmap |
| `0x28` | `u64` | Last accepted request word |
| `0x30` | `u64` | Last successfully queued response word |
| `0x38` | `u8` | Activation state: initializing, dormant, validating, activating, active, rejected, or lease fault |
| `0x39` | `u8` | Activation result/error code |
| `0x3a` | `u16` | Saturating activation-attempt count |
| `0x3c` | `u32` | Last activation request ID |

Readers require exact ABI 1.1, structure size, generation, profile capabilities
and activation state; major-only compatibility is not sufficient.

### Manifest and lease activation

The 128-byte manifest at `0x8ff00040` is C906L-owned and immutable for one boot
generation.  It records its own format and size, generation, contract epoch,
profile ID, ABI, capability/lease widths, final and dormant masks, lease mask,
flags, the 32-byte semantic contract digest, zeroed reserved bytes, and a final
commit word.  Firmware clears the commit, publishes and cleans the body, writes
the commit last, cleans again, then invalidates and verifies exact readback.

For a lease profile, Linux writes the analogous 128-byte request at
`0x8ff000c0` commit-last.  It includes the observed firmware generation, a
nonzero request ID, and the exact ABI/epoch/profile/capability/lease/digest
identity.  C906L invalidates and compares two complete snapshots before any
leased MMIO or PLIC access.  A mismatch is rejected while base services remain
RUNNING and dormant; a post-authorization hardware failure becomes terminal
`LEASE_FAULT` for that boot without taking down mailbox or RPMsg.  Repeating
the exact accepted request is idempotent.

## Linux interface

The out-of-tree GPL control module binds `sophgo,sg2002-c906l-control`, validates
the complete live identity, performs any required lease activation, and only
then exposes:

- `/dev/sg2002-c906l-control`: one opener at a time, one request in flight.
  A write must be exactly eight bytes; a read returns exactly eight bytes.
  `poll()` reports writable only when no request/response is pending and
  readable when the response has arrived.
- `/sys/class/misc/sg2002-c906l-control/device/status`: a text snapshot of ABI,
  state, generation, flags, heartbeat, capabilities, and last request/response.
- `/sys/class/misc/sg2002-c906l-control/device/contract`: the exact profile,
  ID, digest, epoch, ABI, capability masks, lease mask, manifest flags and
  activation policy compiled into the driver.
- `/sys/class/misc/sg2002-c906l-control/device/activation`: the driver outcome
  and exact firmware activation state, result, attempt count and request ID.

There are deliberately no ioctls, `mmap`, generic MMIO proxy, firmware-loading
operations, or peripheral controls.  Raw activation messages are denied and
the receive callback discards unsolicited words when no request is pending.

The second GPL module binds `sophgo,sg2002-c906l-rproc`.  It attaches Linux
remoteproc/rproc-virtio to the firmware-initialized 88-byte resource table,
fixed vrings and buffer pool.  It accepts the base RPMsg service while a lease
is DORMANT or after a rejected/failed lease attempt, allowing control to retry
where safe, and accepts the exact final capabilities once ACTIVE.  Its only
shared-memory write is the virtio status byte used to take the transport
offline; lifecycle methods never reset or stop the core.

The current blocking read has no in-kernel response timeout.  Applications
must use `poll`/`ppoll` with a deadline and treat timeout or a stalled heartbeat
as failure.  Closing waits up to 100 ms for a pending response and then abandons
the transaction.  On C906L, response submission retries for 20 scheduler ticks
(nominally 100 ms) before setting the response-timeout flag.

When `sg2002.auxCore.enable` is set, the image includes
`sg2002-c906l-ctl`.  It opens the endpoint nonblocking through `rustix`, uses
one finite deadline for request readiness and response receipt, and validates
the exact service, opcode, sequence, echoed value, length, and little-endian
wire format.  With no command it first reads stable kernel sysfs snapshots and
requires the exact compiled contract and successful ACTIVE state, then checks
the exact firmware ABI, exact profile capability mask, and a ping:

```console
sg2002-c906l-ctl
sg2002-c906l-ctl contract
sg2002-c906l-ctl activation
sg2002-c906l-ctl --timeout-ms 500 abi
sg2002-c906l-ctl capabilities
sg2002-c906l-ctl ping 0xfeedbeef
sg2002-c906l-ctl --timeout-ms 500 bench 10000
sg2002-c906l-ctl --timeout-ms 500 rpmsg-check 496
```

The benchmark is deliberately sequential because the kernel endpoint permits
one request in flight.  It reports the validated transaction count and
nearest-rank p50, p99, and maximum latency in microseconds.  `stress` is an
alias for `bench`; every iteration retains the same bounded poll and sequence
checks.

A minimal userspace ping, after hardware validation, is:

```python
import os
import select
import struct

fd = os.open("/dev/sg2002-c906l-control", os.O_RDWR | os.O_NONBLOCK)
request = struct.pack("<BBHI", 1, 0x01, 1, 0xfeedbeef)
os.write(fd, request)
poller = select.poll()
poller.register(fd, select.POLLIN)
if not poller.poll(500):
    raise TimeoutError("C906L did not answer within 500 ms")
response = os.read(fd, 8)
assert struct.unpack("<BBHI", response) == (1, 0x81, 1, 0xfeedbeef)
```

## Peripheral ownership and capability matrix

The SG2002 TRM v1.02 routing and memory-map tables are the controlling hardware
source for this matrix.  The older pinned example BSP is implementation
evidence, not an authority that can override the TRM.  Where those sources use
incompatible names, the discrepancy is a blocker and this document does not
guess an IRQ-to-register-bank association.

The C906L PLIC routing table describes what *could* interrupt C906L; it does
not grant ownership.  Except for the explicit Timer4 profile and three mailbox
channels, every functional bank below is owned by Linux/host policy, including
banks Linux leaves disabled.  “Future candidate” means only that an interrupt
is routed to C906L.  Transfer still requires a reviewed driver,
pin/clock/reset/DMA description, Linux quiescence, DT handoff, rollback, and
proof that no other core accesses the bank.

| C906L IRQ | Routed bank | TRM physical range | First firmware owner / C906L capability | Future policy |
| ---: | --- | --- | --- | --- |
| 16 | JPEG codec | `0x0b000000..0x0b010000` | Linux; none | Keep Linux-owned with the video pipeline |
| 17 | H.264 codec | `0x0b010000..0x0b020000` | Linux; none | Keep Linux-owned; concurrent codec work |
| 18 | H.265 codec | `0x0b020000..0x0b030000` | Linux; none | Keep Linux-owned |
| 19 | VC SBM | Codec sub-block; no independent range named in the TRM map | Linux; none | Keep with codec owner |
| 20 | ISP | `0x0a000000..0x0a080000` | Linux; none | **Must remain Linux-owned during ISP work** |
| 21 | SC_TOP | `0x0a080000..0x0a080400` | Linux; none | Keep with display/video subsystem |
| 22 | CSI_MAC0 / VI0 | `0x0a0c2000..0x0a0c4000` | Linux; none | **Must remain Linux-owned during camera work** |
| 23 | CSI_MAC1 / VI1 | `0x0a0c4000..0x0a0c6000` | Linux; none | Keep Linux-owned |
| 24 | LDC | `0x0a0c0000..0x0a0c2000` | Linux; none | Keep with camera/video pipeline |
| 25 | System DMA | `0x04330000..0x04340000` | Linux; none | Shared engine: do not transfer without channel isolation |

Notably absent from the C906L routing table are USB, Ethernet, eMMC, SD0/SD1,
SPI NAND/NOR, MMIO/DTS SPI2 and SPI3, UART2-UART4, PWM0-PWM3, watchdogs 0/1,
Wiegand1/2, timers 0-3, RTC alarm/timer and long-press, VBAT detect, TPU,
temperature/SAR ADC/TRNG, EPHY, and several firewall/DDR events.  MMIO
visibility alone would not make these safe RTOS peripherals; they remain
Linux-owned and are not candidates for ordinary interrupt-driven C906L
service without a separate, reviewed polling/ownership design.  The TRM's
one-based SPI1-SPI4 interrupt names correspond to physical MMIO/DTS SPI0-SPI3;
there is no fifth SPI bank.

No ownership transfer should be represented as a generic userspace MMIO
proxy.  A future service needs a narrow versioned RPMsg ABI and a Linux driver
for the relevant subsystem.  Ownership changes must be atomic and observable:
quiesce Linux, mask IRQ/DMA, transfer clocks/resets/pins, start the RTOS service,
and reverse those steps on failure.

### Static lease manifest

Peripheral handoffs are selected at evaluation/boot time, not by runtime
unbind.  The option is an explicit enumeration:

```nix
sg2002.auxCore.peripherals = [ "timer4" ];
```

There is no `all = true` shortcut.  One generated profile contract atomically:

1. Enables the matching firmware/Cargo feature and embeds a manifest version,
   hash, epoch, and capability bits in the C906L image.
2. Records exact leased MMIO subranges and explicitly C906L-local IRQ metadata
   in the control node.  A build-time guard decompiles the final flattened DTB
   and rejects every enabled Linux `reg` range which overlaps a lease.  It does
   not silently disable nodes: whole-controller leases must supply a reviewed
   board overlay which disables the controller and every child/client, while a
   shared-bank lease such as Timer4 excludes only its channel aperture.
3. Gives the Linux control/remoteproc side the same identity so it can reject a
   mismatched firmware/DT combination.
4. Keeps the firmware service dormant until Linux presents and acknowledges the
   matching lease after boot.

Global clock, reset, and pinctrl banks remain Linux-owned; a lease authorizes
only the predeclared operations needed by its controller, not arbitrary RMW of
those banks.  GPIO should begin with a whole-bank lease because its data and
direction registers are whole-bank R/W.  I2C, SPI, and UART require the entire
controller, pins, and all attached children; DMA additionally requires fixed
channels, request lines, reserved buffers, and an explicit non-coherent cache
protocol.  Media and RTC-island blocks stay Linux-owned until their shared
power/reset/DMA relationships are understood.

The `sophgo,c906l-local-irqs` values describe the C906L interrupt-routing
table.  They are diagnostic ownership metadata, not Linux PLIC interrupt
specifiers; the DT guard deliberately does not compare them with Linux
`interrupts` cells merely because their integers may coincide.

Dynamic transfer can follow only after remoteproc-style stop/reset and
quiescence are proven.  The eventual sequence is Linux client quiescence, DMA
termination, IRQ mask/clear, safe pin state, lease activation and RTOS
acknowledgement; return performs the reverse before Linux resets and reprobes
the device.  Until then, unrouted and unsafe-to-transfer blocks are exposed, if
needed, through narrow Linux-owned RPMsg services rather than direct C906L
MMIO.

### First physical peripheral: Timer4

Timer4, in the shared timer block at `0x030a0000` with C906L IRQ 55, is the
smallest meaningful physical step beyond heartbeat.  The SoC names channels
zero-based while the timer-IP chapter names register groups one-based, so SoC
Timer4 is the chapter's Timer5 group at offset `0x050`: load `0x030a0050`,
control `0x030a0058`, and per-channel read-to-clear EOI `0x030a005c`.  The
packaged bounded self-test has now validated this mapping on SG2002 silicon;
the pinned BSP itself still has no timer driver.

Timer4 needs no external pins, DMA, or electrical side effects.  The first
implementation should lease only Timer4, leave timers 0-3 and 5-7 untouched,
read and validate the already-enabled 25 MHz clock gates/source and deasserted
resets without writing CLKGEN/TOP/RSTGEN, and perform a bounded one-shot test.
The hardware's user-defined mode is periodic, so the ISR must read only the
per-channel EOI and immediately mask/disable Timer4 before publishing pass/fail
and observed latency.  Reading the aggregate EOI is forbidden because it would
clear every channel.

The implementation is a Cargo/Nix feature compiled off by default.  It uses a
typed Rust register interface with fake-MMIO ordering tests, the pinned C BSP
only for PLIC registration, a 100 ms 25 MHz load, and a hard 500 ms FreeRTOS
deadline.  Its ISR reads the channel EOI, masks/disables Timer4, publishes an
atomic completion, and only then returns for PLIC completion.  Clock/reset or
source mismatch performs no Timer or PLIC write.  A timeout tears down only
Timer4 and IRQ55, retains RUNNING/RPMsg, and publishes a terminal lease fault;
capability bit 2 is set only on success.  The Nix module, firmware, FIP, DT,
drivers, CLI and USB runner carry the same selected contract.  The underlying
one-shot mapping passed on silicon under ABI 1.0; the ABI-1.1 Linux-gated path
still requires the cold-cycle validation below.

## Safe RAM-only bring-up and rollback

Do not flash the experimental FIP to SD, eMMC, or SPI flash.  Use the ROM USB
download path so reset/power-cycle returns to the existing persistent boot
medium.  The host runner embeds the C906L fastboot FIP and serializes access
because the underlying ROM downloader cannot select between multiple attached
SG2002 devices.

Build all artifacts on `trex`; `/mnt/Home` is NFS-mounted on the development
machine and is not a suitable build location.  Before connecting hardware,
build the narrow checks/artifacts:

```console
nix build \
  .#checks.x86_64-linux.sg2002-c906l-rust \
  .#checks.x86_64-linux.sg2002-c906l-rust-timer4 \
  .#checks.x86_64-linux.sg2002-c906l-ctl \
  .#checks.x86_64-linux.sg2002-c906l-ctl-timer4 \
  .#checks.x86_64-linux.sg2002-c906l-firmware \
  .#checks.x86_64-linux.sg2002-c906l-firmware-timer4 \
  .#checks.x86_64-linux.sg2002-c906l-control \
  .#checks.x86_64-linux.sg2002-c906l-control-timer4 \
  .#checks.x86_64-linux.sg2002-c906l-remoteproc \
  .#checks.x86_64-linux.sg2002-c906l-remoteproc-timer4 \
  .#checks.x86_64-linux.sg2002-c906l-fip \
  .#checks.x86_64-linux.sg2002-c906l-fip-timer4 \
  .#checks.x86_64-linux.sg2002-c906l-runner \

# Opt-in Timer4 lease/self-test image:
nix build .#sg2002-usb-boot-c906l-timer4
```

`sg2002-usb-boot-c906l` is a mainline-only package: both its `usb-boot` and
`usb-boot-mainline` entry points use the same verified C906L FIP.  It does not
contain the generic package's vendor-FIP runner.  Execute the runner on the host
to which the board is physically attached; the ROM downloader cannot select a
remote USB bus.

Build the matched live-image runner, whose NixOS closure enables
`sg2002.auxCore` and whose FIT therefore contains the same two carveouts as its
firmware-bearing FIP:

```console
runner=$(nix build --no-link --print-out-paths \
  .#boards.licheerv.mainline.live.usb-c906l.usb-boot)
sudo -n env NANOKVM_ATTACH=none NANOKVM_STATUS_LISTEN=0 \
  "$runner/bin/usb-boot" --uboot-only --attempts 3 --wait 120
```

Run this only with exactly one intended SG2002 ROM gadget (`3346:1000`)
attached.  After the U-Boot-only and rollback checks below, omit
`--uboot-only` to boot the matching Linux FIT.  The runner keeps its rootfs
service alive until interrupted.

The initial run should be supervised by host-side USB/UART logging, a bounded
deadline, and a known power-cycle path.  A cautious sequence is:

1. Run the embedded C906L FIP with `--uboot-only`; require U-Boot fastboot
   (`18d1:d00d`) to enumerate.  On the tested USB path FSBL has already started
   C906L, so the same runner invocation validates two exact stable ABI-1.1
   status/manifest snapshots and a forward heartbeat.  Timer4 must still be
   DORMANT with base capabilities at this point.  If reset state instead
   shows the core held, the runner additionally verifies the FIP-loaded payload
   CRC and performs the reset-vector/release sequence before those live checks.
   A manual read-only U-Boot dump of `0x8ff00000..0x8ff000bf` remains useful for
   diagnosis.
2. Reset/power-cycle and confirm the ordinary persistent image still boots.
3. Run again with the matching FIT.  Require Linux to boot, both generated-
   contract modules to bind, the misc device to appear, and `sg2002-c906l-ctl`
   to report the exact contract and ACTIVE activation state.  For Timer4,
   require one nonzero activation request ID/attempt and capabilities `0x0f`.
4. Exercise `sg2002-c906l-ctl check`, `rpmsg-check`, bounded mailbox/RPMsg
   stress, sequence matching, simultaneous-open refusal, and heartbeat progress.
5. Reset/power-cycle again and confirm the original image and its full memory
   map are restored.

`--skip-fip` does not establish which firmware started a core that is already
running.  Such an ambiguous attach fails closed unless the operator also passes
`--accept-running-c906l`, after independently proving that the exact matching FIP
was transferred.  Explicit attach still validates the full immutable contract,
pre-Linux activation policy, stable generation and an advancing heartbeat, but
cannot CRC a live payload whose data and BSS have already changed.  A core
observed held in reset always follows the stronger CRC and release path,
including with `--skip-fip`.

If U-Boot or Linux stalls, the heartbeat stops, or a response times out, do not
poke reset-controller registers from Linux.  Stop the host transfer, hard-reset
or power-cycle the board, and boot the known-good non-C906L FIP.  That default
FIP now encodes `BLCP_2ND_SIZE=0` and `BLCP_2ND_RUNADDR=0`, while its ordinary
DTB exposes the complete 256 MiB; it is the rollback state.  A watchdog is an
additional safeguard, not proof that resetting C906L with active bus traffic
is safe.

### Hardware observations (2026-09-04)

On `strix-2`, the ROM gadget appeared at physical path `3-1` as
`3346:1000`, serial `123456789ABC`.  Attempt 1 transferred the complete
337,920-byte FIP, including the verified 12,288-byte C906L payload, and U-Boot
enumerated as Sipeed `18d1:d00d`.  No persistent media was written.

`fastboot reboot` returned success and disconnected the gadget, but neither the
ROM gadget nor another board USB personality returned within 30 seconds.  A
subsequent clean reboot of otherwise-idle `strix-2` also produced no board USB
event.  This confirms that a host reboot is not a reliable board power-cycle;
do not repeat that software-reset path or treat a host reboot as board power
control.

After a physical cold cycle, `bdinfo` showed U-Boot reserving
`0x8e6fd320..0x8fffffff`; both original C906L carveouts were inside its runtime
and malloc arena and had been cleared.  For a bounded diagnostic only, the same
firmware was staged directly at `0x88000000`, with status at `0x88100000`, and
C906L was released using the vendor's four-register sequence.  U-Boot verified
the 12,424-byte image as CRC32 `0x961ca69b`; the firmware then published magic
`0x4d564b4e`, ABI 1, structure size 64, RUNNING state, generation 1, capability
bits 0 and 1, and an advancing heartbeat (`0xae` then `0xc3`).

The diagnostic addresses are not the production contract.  Production remains
at the vendor-proven final 2 MiB (`0x8fe00000..0x90000000`) and uses a dedicated
U-Boot variant with `CONFIG_SYS_MEM_TOP_HIDE=0x200000`.  A follow-up production
boot preserved both regions and found C906L already out of reset with a valid
ABI/capability record and advancing heartbeat, proving that FSBL starts it on
this USB BootROM path before U-Boot.  Because running firmware mutates its data,
the same-invocation runner uses that live proof rather than a post-start payload
CRC.  The held-reset fallback still CRCs the exact payload before releasing it.

That follow-up also exposed one narrower hole: the running U-Boot allocated EFI
pages at `0x8fffd000..0x8fffffff` even though its relocation and malloc honored
`SYS_MEM_TOP_HIDE`.  LMB still described the original full DRAM bank.  The local
`CONFIG_LMB_LIMIT_DMA_BELOW_RAM_TOP` patch described above closes that mismatch.
The next hardware boot showed one continuous no-overwrite reservation from
`0x8e4fd320..0x8fffffff`, covering both complete C906L carveouts.  EFI's three
pages moved below it to `0x8e4fa000..0x8e4fcfff`; no LMB allocation remained in
`0x8fe00000..0x90000000`.

The cross-built `sg2002-c906l-ctl` was then copied into the ephemeral base
firmware system and run against `/dev/sg2002-c906l-control`.  Its default check
reported ABI 1.0, capabilities `0x00000003`, and a validated ping.  A 10,000
transaction benchmark with a 100 ms per-transaction deadline reported p50
110.880 us, p99 153.160 us, and maximum 252.400 us.  The mailbox IRQ count rose
by exactly 10,000 and firmware flags remained zero.  This validates the base
mailbox, kernel endpoint, Rust userspace transport, and measurement path only;
it was not used as evidence for the then-untested Timer4/LMB changes.

A later boot of the complete `usb-c906l-timer4` catalog artifact validated those
pieces together.  C906L published generation 2, RUNNING state, flags zero and
capabilities `0x7`, so the runner accepted the Timer4 IRQ-55 self-test before
Linux handoff.  The CLI was present in the NixOS system path and its default
ABI/capability/ping check passed.  A further 10,000-transaction run reported
p50 107.760 us, p99 151.720 us and maximum 883.600 us; Linux recorded exactly
10,003 mailbox interrupts for the three default queries plus the benchmark,
and firmware flags remained zero.

## Shared-DDR and RPMsg status

The mailbox must remain a low-latency doorbell/control plane.  Putting pointers
or bulk buffers into its eight-byte slot would reproduce the vendor command
queue's weak bounds, lifetime, and concurrency model.

ABI 1.1 completes the foundational transport without importing OpenAMP or
libmetal into firmware: Rust implements the small fixed virtio/RPMsg device,
while Linux uses its standard remoteproc, rproc-virtio and rpmsg-char stack.
The resource table, two vrings, buffer pool, ownership directions and cache
maintenance are generated from one contract.  Dedicated mailbox channels keep
control requests separate from vq kicks and notifications.

The remaining forward path is:

1. Validate the exact ABI-1.1 base and Timer4 profiles on silicon, including
   DORMANT observation before Linux, activation, RPMsg echo/cache stress, and
   p50/p99/p99.9 mailbox and data-plane latency.
2. Expose narrow RPMsg services and bind them to appropriate Linux subsystem
   drivers.  Use RPMsg for negotiation/control and shared-DDR buffers/rings for
   bulk or hard-latency data.
3. Add stop/start only after bus quiescence, reset-register privilege, firmware
   authentication, crash containment, and watchdog recovery have been proven.
   If reset needs M-mode mediation, define a proper Sophgo vendor SBI extension
   rather than the downstream private syscall/SBI-BASE modifications.

The RTOS must validate every RPMsg endpoint, length, index, and state
transition.  Firmware remains immutable/root-selected through Nix; untrusted
userspace must never choose firmware bytes, physical addresses, DMA targets,
or raw peripheral operations.
